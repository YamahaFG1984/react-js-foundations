Chapter 16

数据获取与持久化

原书这一章的取数代码藏着一个所有人都会踩的 bug：请求竞态。修好它需要的正是第 11 章那个清理函数。

chapter16/Restful.js · Restful2.js · Clicker1–4.js · chapter11/ShippingAddress.js · WeatherWidget.js

先看清竞态问题

原书 ShippingAddress.js 在 useEffect 里按邮编取数，没有任何清理。 用户手快连输两个邮编时，会发生这件事：

React 19 · 正确的取数写法
import { useEffect, useState } from "react";

type Repo = { id: number; name: string };

export default function Repos({ user }: { user: string }) {
  const [repos, setRepos] = useState<Repo[]>([]);
  const [status, setStatus] =
    useState<"idle" | "loading" | "error">("idle");

  useEffect(() => {
    const ctrl = new AbortController();
    setStatus("loading");

    fetch(`https://api.github.com/users/${user}/repos`,
          { signal: ctrl.signal })
      .then((r) => {
        if (!r.ok) throw new Error(String(r.status));
        return r.json();
      })
      .then((data: Repo[]) => { setRepos(data); setStatus("idle"); })
      .catch((e) => {
        if (e.name !== "AbortError") setStatus("error");
      });

    return () => ctrl.abort();   // ← 关键的一行
  }, [user]);

  if (status === "loading") return <p>Loading…</p>;
  if (status === "error") return <p>加载失败，请重试</p>;
  return <ul>{repos.map((r) =>
    <li key={r.id}>{r.name}</li>)}</ul>;
}
Vue 3 · 同样的逻辑
<script setup lang="ts">
import { ref, watch, onWatcherCleanup, toRef } from "vue";

type Repo = { id: number; name: string };
const props = defineProps<{ user: string }>();

const repos = ref<Repo[]>([]);
const status = ref<"idle" | "loading" | "error">("idle");

watch(toRef(props, "user"), async (user) => {
  const ctrl = new AbortController();
  onWatcherCleanup(() => ctrl.abort());   // ← 同样是关键一行
  status.value = "loading";
  try {
    const r = await fetch(
      `https://api.github.com/users/${user}/repos`,
      { signal: ctrl.signal });
    if (!r.ok) throw new Error(String(r.status));
    repos.value = await r.json();
    status.value = "idle";
  } catch (e: any) {
    if (e.name !== "AbortError") status.value = "error";
  }
}, { immediate: true });
</script>

<template>
  <p v-if="status === 'loading'">Loading…</p>
  <p v-else-if="status === 'error'">加载失败，请重试</p>
  <ul v-else>
    <li v-for="r in repos" :key="r.id">{{ r.name }}</li>
  </ul>
</template>
实践中：别手写这些

上面两段代码只解决了竞态，还没处理缓存、去重、重试、焦点重取、离线。 生产项目直接用数据层库：React 侧是 TanStack Query（原 React Query）或路由的 loader； Vue 侧是 TanStack Query 的 Vue 版或 @vueuse/core 的 useFetch。 原书用的 axios-hooks 已经很少见了。

localStorage：原书 Clicker 系列的坑

Clicker3.js 写的是 useState(Number(localStorage.getItem("counter")) || 0)。 这行代码在每一次渲染都会读一次 localStorage——虽然只有第一次的返回值被采纳，但同步的磁盘读取白白执行了。 正确写法是传函数（惰性初始化）：

// ❌ 每次渲染都执行 getItem
const [count, setCount] = useState(Number(localStorage.getItem("counter")) || 0);

// ✅ 只在首次挂载时执行一次
const [count, setCount] = useState(() => {
  try {
    return Number(localStorage.getItem("counter")) || 0;
  } catch {
    return 0;   // 隐私模式下 localStorage 可能直接抛异常
  }
});

useEffect(() => {
  localStorage.setItem("counter", String(count));
}, [count]);

Vue 侧对应的是 @vueuse/core 的 useLocalStorage("counter", 0)——一行搞定读写同步， 而且跨标签页也会同步。React 侧要做到跨标签页同步，需要 useSyncExternalStore 订阅 storage 事件。

小结
  • effect 里取数必须在清理函数中 abort 或设置忽略标志，否则会有竞态。
  • useState(fn) 传函数才是惰性初始化，传值会每次渲染都计算。
  • 真实项目用 TanStack Query 一类的数据层，别手写缓存与重试。
  • React Router 7 的 loader 能把取数提前到导航阶段，避免加载闪烁。
