并发渲染：让渲染可以被打断

这是 React 18 最本质的变化，也是 Fiber 那套结构存在的理由。在此之前，一次渲染一旦开始就必须跑完， 中途用户的输入只能干等。

React 19 · 并发 API 速览
import { useState, useTransition, useDeferredValue,
         Suspense, use } from "react";

function Search() {
  const [query, setQuery] = useState("");
  const [isPending, startTransition] = useTransition();
  const [results, setResults] = useState<string[]>([]);

  function onChange(v: string) {
    setQuery(v);                       // 紧急：立刻上屏
    startTransition(() => {            // 过渡：可被打断
      setResults(expensiveFilter(v));
    });
  }

  return (
    <>
      <input value={query}
        onChange={(e) => onChange(e.target.value)} />
      <ul style={{ opacity: isPending ? 0.6 : 1 }}>
        {results.map((r) => <li key={r}>{r}</li>)}
      </ul>
    </>
  );
}

  const user = use(userPromise);      // 挂起直到 resolve

Vue 3 · 对应能力
<script setup lang="ts">
import { ref, computed, defineAsyncComponent } from "vue";

// Vue 没有 useTransition / useDeferredValue。
// 同类问题的常规解法：
// 1) 防抖 + computed
import { refDebounced } from "@vueuse/core";
const query = ref("");
const deferred = refDebounced(query, 150);
const results = computed(() => expensiveFilter(deferred.value));

// 2) 长列表用虚拟滚动（vue-virtual-scroller）

// 3) <Suspense> 存在，但仍是实验性 API
// 4) 异步组件 + 加载态
const Profile = defineAsyncComponent({
  loader: () => import("./Profile.vue"),
  loadingComponent: Skeleton,
});
</script>

<template>
  <input v-model="query" />
  <ul><li v-for="r in results" :key="r">{{ r }}</li></ul>

  <!-- 实验性 -->
  <Suspense>
    <Profile />
    <template #fallback><Skeleton /></template>
  </Suspense>
</template>

小结
  • 并发渲染 = 把长渲染切片，让紧急更新可以插队。
  • useTransition / useDeferredValue 是你日常唯一会碰到的两个并发 API。
  • use() + Suspense 让"读取异步数据"变成渲染期的普通操作。
  • Vue 目前不提供并发渲染，同类问题靠防抖、虚拟滚动、异步组件解决。
