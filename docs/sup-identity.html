补 B · 书里没有

状态住在树的哪个位置

上一节说 state 是"这次渲染的快照"。那这份数据究竟存在哪？答案不是"存在组件里"——是存在树中的那个位置上。

你写的 Counter 只是一个函数，它被调用一百次就产生一百份独立的 state。区分它们的不是函数本身， 而是 React 在树里给它安排的位置：父节点 + 在同层中的次序 + key。位置不变，state 就一直在；位置一变，state 就没了。

React · 用 key 重置，而不是用 effect 同步
// ❌ 常见但错误：用 effect 把 props 同步进 state
function ProfileForm({ userId, initialName }: Props) {
  const [name, setName] = useState(initialName);

  useEffect(() => {
    setName(initialName);      // 换用户时重置
  }, [userId]);                // 会多渲染一次，还容易漏字段

  return <input value={name}
    onChange={(e) => setName(e.target.value)} />;
}

// ✅ 让 React 自己重建：换 key 即可
function ProfileForm({ initialName }: { initialName: string }) {
  const [name, setName] = useState(initialName);
  return <input value={name}
    onChange={(e) => setName(e.target.value)} />;
}

// 父组件
<ProfileForm key={userId} initialName={user.name} />

// 一个约定：以 initial / default 开头的 prop，
// 意思就是"只在初始化时读一次，之后不再跟随"。
Vue · 同样的两种写法
<!-- ❌ 用 watch 同步 -->
<script setup lang="ts">
const props = defineProps<Props>();
const name = ref(props.initialName);
watch(() => props.userId, () => {
  name.value = props.initialName;
});
</script>

<!-- ✅ 让 key 触发重建 -->
<script setup lang="ts">
const props = defineProps<{ initialName: string }>();
const name = ref(props.initialName);
</script>
<template>
  <input v-model="name" />
</template>

<!-- 父组件 -->
<ProfileForm :key="userId" :initial-name="user.name" />
小结
  • state 挂在「树中的位置 + key」上，不挂在组件函数上。
  • 同位置换 props → 保留；换 key → 重建；type 变了 → 重建。
  • 需要"换数据就清空"时，给组件一个 key，别写 effect 去同步。
  • initialXxx 这类命名是在告诉调用者：这个值只读一次。
