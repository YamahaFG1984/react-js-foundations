Chapter 03

JSX 不是模板

花括号里是 JavaScript 表达式，不是模板语法。理解这一条，本章所有"技巧"都变成常识。

chapter03/ConditionalWelcome{,2,3}.js · FragmentExample{1,2}.js · ImmediateInvoke.js · SearchBox/

原书清单在做什么

三个 ConditionalWelcome 展示了条件渲染的三种写法，ImmediateInvoke.js 甚至在 JSX 里塞了个立即执行函数。 它们背后是同一条规则：{} 里必须能求值成一个值，所以 if 语句不行，三元和 && 行。

语法对照

要做的事React（JS 表达式）Vue（模板指令）
插值{name}{{ name }}
二选一{ok ? <A/> : <B/>}v-if / v-else
有则显示{ok && <A/>}v-if="ok"
显示但隐藏style={{display: ok?"":"none"}}v-show="ok"
列表{list.map(x => <li key={x.id}>)}v-for="x in list" :key="x.id"
不产生额外节点<>…</>（Fragment）模板天然支持多根节点
class 属性className="a b":class="['a', {b: ok}]"
label 关联htmlFor="id"for="id"（原样）
内联样式style={{fontSize: 24}}（对象）:style="{fontSize:'24px'}"
自定义属性data-size="XL"（原样保留）同左

右边那些 v-* 是 Vue 编译器认识的特殊标记；左边则没有任何特殊标记，全是 JavaScript。这就是"JSX 不是模板"的实际含义： 你不需要框架给你提供 v-for，因为 Array.prototype.map 已经在那儿了。代价是模板里能写出任意复杂的逻辑，需要靠约定来克制。

条件渲染的三种写法

React 19 · Welcome.tsx
// 写法 1：提前算好，存进变量（最好读）
function Welcome({ loggedIn }: { loggedIn: boolean }) {
  const header = loggedIn ? <Header /> : <Login />;
  return <div>{header}</div>;
}

// 写法 2：只在为真时出现
function Welcome2({ loggedIn }: { loggedIn: boolean }) {
  return <div>{loggedIn && <Header />}</div>;
}

// 写法 3：行内三元（分支短时用）
function Welcome3({ loggedIn }: { loggedIn: boolean }) {
  return <div>{loggedIn ? <Header /> : <Login />}</div>;
}
Vue 3 · Welcome.vue
<script setup lang="ts">
defineProps<{ loggedIn: boolean }>();
</script>

<template>
  <!-- 写法 1/3 合一：v-if / v-else -->
  <div>
    <Header v-if="loggedIn" />
    <Login v-else />
  </div>

  <!-- 写法 2：只有 v-if，没有 else -->
  <div>
    <Header v-if="loggedIn" />
  </div>
</template>
&& 的经典陷阱

{count && <Badge/>} 在 count === 0 时会把 0 渲染到页面上——因为 0 && x 求值为 0，而 React 会渲染数字。 要么写 {count > 0 && …}，要么写 {count ? … : null}。Vue 的 v-if="count" 不会有这个问题，因为它只判真假、不输出判断结果。

小结
  • {} 里只能放表达式；需要语句就在 return 之前写，或者抽成函数。
  • <X/> 产生一个描述对象，不等于执行了 X。
  • Fragment（<>…</>）解决的是"必须单根"的限制；Vue 3 的模板本来就支持多根节点。
