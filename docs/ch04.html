Chapter 04

组件、children 与组合

这一章原书用了大量 class 组件。今天 class 已经不是主流，但它留下的两个概念——组合与重渲染传播——一天也没过时。

chapter04/ToDoClass.js · ToDoFunction.js · ThingsThatILike.js · clone-element/ · ReactMemoExample.js · LeakyCounter.js

class 与函数，写法之外的差别

原书把同一个待办列表写了两遍（ToDoClass.js / ToDoFunction.js）。除了少打很多字，函数组件真正的区别在于： 它没有 this，所以不需要 bind；它每次渲染都是一次全新的函数调用。 原书 UnboundFunction.js 与 BoundFunction.js 演示的那个 this 陷阱，在函数组件里根本不存在。

React 19 · ToDo.tsx（函数组件 + TS）
import { useState, type FormEvent } from "react";

type Todo = { id: string; text: string };

export default function ToDo() {
  const [item, setItem] = useState("");
  const [list, setList] = useState<Todo[]>([]);

  function handleSubmit(e: FormEvent) {
    e.preventDefault();
    if (!item.trim()) return;
    // 造新数组，并给每条数据一个稳定 id（为什么：见「补 A」）
    setList([...list, { id: crypto.randomUUID(), text: item }]);
    setItem("");
  }

  return (
    <form onSubmit={handleSubmit}>
      <input
        value={item}
        onChange={(e) => setItem(e.target.value)}
        placeholder="what to do?"
      />
      <button type="submit">Add</button>
      {list.map((todo) => (
        <p key={todo.id}>{todo.text}</p>
      ))}
    </form>
  );
}
Vue 3 · ToDo.vue
<script setup lang="ts">
import { ref } from "vue";

const item = ref("");
const list = ref<{ id: string; text: string }[]>([]);

function handleSubmit() {
  if (!item.value.trim()) return;
  // 可以直接改；key 同样要用稳定 id
  list.value.push({ id: crypto.randomUUID(), text: item.value });
  item.value = "";
}
</script>

<template>
  <form @submit.prevent="handleSubmit">
    <input v-model="item" placeholder="what to do?" />
    <button type="submit">Add</button>
    <p v-for="todo in list" :key="todo.id">{{ todo.text }}</p>
  </form>
</template>
第一个真正的分歧：能不能改

Vue 那边 list.value.push(...) 直接生效——因为数组被 Proxy 包过，改动会被拦截并通知订阅者。 React 这边 必须造一个新数组：setList([...list, newTodo])。 如果你写 list.push(newTodo); setList(list)，React 拿到的是同一个引用，判定"没变"，界面不会更新。 这不是 React 笨，而是它靠"引用是否改变"来判断，代价换来的是可预测性——数据永远不会在你没注意的地方被偷偷改掉。

组合：children 就是一个普通 prop

原书 ThingsThatILike.js 把一个 <ul> 塞进 <ThingsThatAreFunny> 里。这个"塞进去"的动作，机制上非常朴素：

React 19 · 默认插槽 + 具名插槽
import type { ReactNode } from "react";

type Props = {
  title: ReactNode;          // 具名插槽
  children: ReactNode;       // 默认插槽
  footer?: ReactNode;        // 可选插槽
};

function Panel({ title, children, footer }: Props) {
  return (
    <section>
      <h2>{title}</h2>
      {children}
      {footer && <footer>{footer}</footer>}
    </section>
  );
}

// 使用
<Panel title={<b>笑话集</b>} footer={<small>完</small>}>
  <ul><li>…</li></ul>
</Panel>
Vue 3 · Panel.vue
<script setup lang="ts">
// 插槽不用声明类型也能用；要类型时：
defineSlots<{
  default(): any;
  title(): any;
  footer?(): any;
}>();
</script>

<template>
  <section>
    <h2><slot name="title" /></h2>
    <slot />
    <footer v-if="$slots.footer"><slot name="footer" /></footer>
  </section>
</template>

<!-- 使用 -->
<Panel>
  <template #title><b>笑话集</b></template>
  <ul><li>…</li></ul>
  <template #footer><small>完</small></template>
</Panel>

重渲染是会传染的

原书用 PureComponent 和 React.memo 处理这个问题。先看清楚问题本身：

Vue 侧没有对应物

Vue 组件的更新由依赖追踪驱动：Child 只有在它读过的响应式数据变化时才重新渲染。 所以 Vue 里没有 memo、没有 useCallback，也很少有人讨论"重渲染传播"。 代价是你要记得把状态放进 ref/reactive，否则它根本不在追踪范围内。

顺带一提：LeakyCounter

原书 LeakyCounter.js 在 componentDidMount 里开了个 setInterval 却没清理，组件卸载后定时器还在跑并调用 setState； NoLeakCounter.js 补上 componentWillUnmount 修好了它。函数组件里这对生命周期合并成了 useEffect 的返回值， 详见 第 11 章的时序图。

小结
  • 写新代码不用 class；this 绑定问题随之消失。
  • React 的状态更新必须产生新引用；Vue 可以就地修改。
  • children 只是一个 prop，因此组合能力天然存在，不需要插槽语法。
  • memo 依赖 props 引用稳定；React Compiler 正在把这件事自动化。
