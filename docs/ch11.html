Chapter 11

Hooks 的规则从何而来

"只能在顶层调用、不能放进 if 里"——这条规则听起来武断。看一眼 React 内部怎么存 Hook 数据，它就变成了唯一可能的设计。

chapter11/NumberGuessing.js · Timer{,Restart,Once,Conditional}Demo.js · ReducerCounter.js · useZipLookup.js · CallMe.js · CallMeFixed.js · CountingBox.js

为什么 Hook 不能写在条件里

函数组件没有 this，那 useState 把值存在哪？答案是存在这个组件的 Fiber 节点上， 一个按调用顺序排列的列表。React 不知道你的变量叫什么，它只知道"这是本次渲染的第几个 Hook"。

Vue 为什么没有这条规则

setup() 在组件的一生中只执行一次，ref() 创建的对象直接被局部变量持有——不需要"槽位"， 自然也就没有顺序要求。你完全可以在 if 里 const x = ref(0)。 这一条差异，正是导读那张大图的直接后果。

useEffect：什么时候跑，什么时候清理

原书用四个 Timer 例子演示了依赖数组的三种形态（TimerDemo 无第二参数、TimerOnceDemo 传 []、 TimerConditionalDemo 传 [gameNumber]）。把它们放到同一条时间轴上看，规律一目了然：

React 19 · useEffect 的三种形态
import { useEffect, useState } from "react";

export default function Timer() {
  const [count, setCount] = useState(0);
  const [gameNumber, setGameNumber] = useState(0);

  useEffect(() => {
    let t = 0;
    const id = setInterval(() => console.log(t++), 1000);
    return () => clearInterval(id);   // ← 必须清理
  }, [gameNumber]);   // 只有换一局才重启计时器

  return (
    <>
      <h1>Game {gameNumber}</h1>
      <button onClick={() => setCount((c) => c + 1)}>
        {count}
      </button>
      <button onClick={() => setGameNumber((g) => g + 1)}>
        New Game
      </button>
    </>
  );
}
Vue 3 · 生命周期 + watch
<script setup lang="ts">
import { ref, watch, onWatcherCleanup } from "vue";

const count = ref(0);
const gameNumber = ref(0);

// 依赖显式写在第一个参数里，语义等价于 [gameNumber]
watch(gameNumber, () => {
  let t = 0;
  const id = setInterval(() => console.log(t++), 1000);
  // Vue 3.5+：在副作用内部注册清理
  onWatcherCleanup(() => clearInterval(id));
}, { immediate: true });   // immediate ≈ 挂载时也跑一次
</script>

<template>
  <h1>Game {{ gameNumber }}</h1>
  <button @click="count++">{{ count }}</button>
  <button @click="gameNumber++">New Game</button>
</template>

Vue 的 watchEffect 在运行时记录你读过哪些响应式数据，自动建立依赖； React 的依赖数组要你自己写对。写少了会读到过期的值（原书 CallMe.js 就是这个问题）， 写多了会无谓地重跑。装 eslint-plugin-react-hooks 的 exhaustive-deps 规则，别关掉它。

useReducer：状态变复杂时的出口

React 19 · ReducerCounter.tsx
import { useReducer } from "react";

type State = { count: number };
type Action =
  | { type: "increment"; payload: number }
  | { type: "decrement"; payload: number }
  | { type: "reset" };

function reducer(state: State, action: Action): State {
  switch (action.type) {
    case "increment":
      return { count: state.count + action.payload };
    case "decrement":
      return { count: state.count - action.payload };
    case "reset":
      return { count: 0 };
  }   // TS 会检查是否覆盖了所有 action
}

export default function Counter() {
  const [state, dispatch] = useReducer(reducer, { count: 0 });
  return (
    <>
      Count: {state.count}
      <button onClick={() =>
        dispatch({ type: "decrement", payload: 4 })}>-4</button>
      <button onClick={() =>
        dispatch({ type: "increment", payload: 4 })}>+4</button>
    </>
  );
}
Vue 3 · 组合式函数封装同样逻辑
<script setup lang="ts">
import { ref } from "vue";

// Vue 没有 useReducer；状态复杂时直接封装成组合式函数
function useCounter(initial = 0) {
  const count = ref(initial);
  return {
    count,
    increment: (n: number) => { count.value += n; },
    decrement: (n: number) => { count.value -= n; },
    reset: () => { count.value = 0; },
  };
}

const { count, increment, decrement } = useCounter();
// 跨组件共享时，把这段搬进 Pinia 的 defineStore
</script>

<template>
  Count: {{ count }}
  <button @click="decrement(4)">-4</button>
  <button @click="increment(4)">+4</button>
</template>

自定义 Hook：把逻辑抽出来

原书 useZipLookup.js 把"输入邮编 → 查城市州名"的逻辑抽成了自定义 Hook。这是 Hooks 最大的价值： 逻辑复用不再需要 HOC 或 render props。规则很简单——函数名以 use 开头，内部可以调其他 Hook。

React 19 · useZipLookup.ts
import { useEffect, useState } from "react";

type Address = { city: string; state: string } | null;

export function useZipLookup(zipcode: string) {
  const [address, setAddress] = useState<Address>(null);
  const [loading, setLoading] = useState(false);

  useEffect(() => {
    if (!zipcode) return;
    const ctrl = new AbortController();   // 原书缺这一步
    setLoading(true);
    fetch(`/api/zip/${zipcode}`, { signal: ctrl.signal })
      .then((r) => r.json())
      .then((d) => setAddress({ city: d.City, state: d.State }))
      .catch((e) => { if (e.name !== "AbortError") throw e; })
      .finally(() => setLoading(false));
    return () => ctrl.abort();   // 邮编再变就取消上一个请求
  }, [zipcode]);

  return { address, loading };
}
Vue 3 · useZipLookup.ts
import { ref, watch, onWatcherCleanup, type Ref } from "vue";

type Address = { city: string; state: string } | null;

export function useZipLookup(zipcode: Ref<string>) {
  const address = ref<Address>(null);
  const loading = ref(false);

  watch(zipcode, async (zip) => {
    if (!zip) return;
    const ctrl = new AbortController();
    onWatcherCleanup(() => ctrl.abort());
    loading.value = true;
    try {
      const r = await fetch(`/api/zip/${zip}`, { signal: ctrl.signal });
      const d = await r.json();
      address.value = { city: d.City, state: d.State };
    } finally {
      loading.value = false;
    }
  }, { immediate: true });

  return { address, loading };
}
useMemo / useCallback 正在退场

原书 CallMe.js → CallMeFixed.js 演示了用 useCallback 稳定函数引用， 好让 useEffect 的依赖数组不至于每次都变。这类代码 90% 是在给 React 的默认行为打补丁。 React Compiler 会在构建时分析出哪些值真正需要缓存并自动插入记忆化， 官方的方向是让你不再手写这两个 Hook。新项目可以开启它，然后基本忘掉 useMemo。

小结
  • Hook 数据按调用顺序存在 Fiber 的槽位里——这就是全部规则的来源。
  • useEffect 在提交并绘制之后执行；返回的清理函数在下次 effect 前和卸载时运行。
  • 依赖数组要手写对；Vue 的 watchEffect 自动收集，这是两边最实质的体验差别。
  • 自定义 Hook / 组合式函数是两边共同的逻辑复用答案，写法几乎一样。
  • StrictMode 下 effect 跑两次是有意为之，用来暴露缺失的清理逻辑。
