Chapter 15

工具链：webpack → Vite

原书手搭了 webpack + Babel + Jest。这条路今天没人走了，但知道每个环节在干什么，出问题时才不至于抓瞎。

chapter15/custom-toolchain/webpack.config.js · babel.config.json · package.json

原书清单在做什么

三个配置文件各管一件事：babel.config.json 里的 @babel/preset-react 负责把 JSX 变成函数调用， @babel/preset-env 负责把新语法降级；webpack.config.js 把 babel-loader 挂到 .js 文件上， 再把所有模块打成一个包；package.json 里的 Jest 负责测试。今天这三件事被一个工具全包了。

React · 从零建项目
npm create vite@latest my-app -- --template react-ts
cd my-app && npm install

npm i -D vitest @testing-library/react \
         @testing-library/jest-dom jsdom
npm i -D eslint-plugin-react-hooks

# 可选：开启 React Compiler，自动记忆化
npm i -D babel-plugin-react-compiler

# vite.config.ts
# export default defineConfig({
#   plugins: [react({ babel: { plugins: [
#     ["babel-plugin-react-compiler", {}]
#   ]}})],
#   test: { environment: "jsdom", globals: true },
# });

npm run dev     # 冷启动通常 < 1s
Vue · 从零建项目
npm create vue@latest my-app
# 交互式勾选 TypeScript / Router / Pinia / Vitest
cd my-app && npm install

# 类型检查（.vue 文件 tsc 看不懂，需要它）
npm i -D vue-tsc

# package.json
# "build": "vue-tsc -b && vite build"

npm run dev     # 同样基于 Vite
小结
  • Babel/SWC 负责 JSX 与语法降级，打包器负责模块合并——两件事，别混为一谈。
  • Vite 开发期不打包，靠原生 ESM；生产期照常打包。
  • React 和 Vue 今天共用 Vite，差别只是一个插件。
  • CRA 已死；测试用 Vitest + Testing Library。
